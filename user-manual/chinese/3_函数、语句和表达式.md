## 表达式、语句和函数

## 表达式

zinc 语言不是一个表达式语言。
1. `break` `continue` `return` `goto` `panic`等关键字，只能用在语句中，不能直接用在表达式中。
2. 只有表达式可以产生一个值。语句不可以。
3. 语句可以包含表达式，但表达式不可以直接包含语句。lambda 表达式除外，它可以包含语句，但是它包含的语句中的 return/break/continue 只影响 lambda 内部，lambda 对外依然表现为表达式的特征，不能做控制流转移。

如果用户需要在一个表达式中，按顺序执行较为复杂的语句，并最终产生一个值，那么请使用 lambda 并立即调用。
lambda 内部的控制流语句，只在 lambda 的函数体内起作用，对外部的表达式无影响。

### 运算符表达式

#### `Result` 类型

Zinc 使用 `Result<R, E>` 作为错误处理的主要机制。它是标准库中定义的一个 enum：
```
enum Result<R, E> {
    Ok(R), Err(E)
}
```

`Result<R, E>` 中的 `E` 代表错误信息。用户可以用任何类型来描述错误信息。

* 如果错误的可能性只有非常有限的几种，那么设计一个 enum 作为错误信息就很合理。

* 如果我们只需要错误信息进行打印 log，那么简单地用字符串作为错误类型也没问题。

* 如果我们需要对错误类型进行多层级的分门别类，那么设计一组 `trait MyBussinessError` 及其继承体系，用 `*MyBussinessError` 作为返回的错误类型也是很好的设计。

* 如果函数定义方确实不需要调用方关心具体的错误类型，那么统一返回 `Result<R, *Any>` 就是了。任何错误类型 box 一下之后，都能转换为 `*Any`。
调用方可以按需向下转型，只处理自己需要处理的那部分错误类型。

* 如果我们希望调用方能拿到错误发生的时候的函数调用栈，可以用自定义类型把标准库中的 `BackTrace` 类型包裹起来作为错误类型。
`BackTrace` 类型可以描述当前的调用栈，把它作为错误信息的一部分向外传递即可。

#### `?` 运算符

`?` 运算符是后缀运算符，使用方式为：`expr?`。

`?` 运算符主要就是为了配合 `Result` 类型使用的。 `?` 运算符要求它前面的这个表达式的类型为 `Result`。

> **计划中的功能**：后续再支持 `?` 运算符的重载，让它可以支持自定义类型。

`let x = expr?;` 语句的执行语义为：

```
match(expr) {
    Ok(r) => {
        let x = r;
    }
    Err(e) => {
        return Err(e);
    }
}
```

因为它会导致整个函数提前返回，所以它对这个函数的返回类型是有要求的。
如果 `expr` 的类型是 `Result<R1, E1>`，函数的返回类型是 `Result<R2, E2>`，那么要求 `E2` 能自然隐式转换为 `E1`，或者 `E2` 实现了 `From<E1>` 这个 trait。
这样编译器才有能力把 `E1` 转换为 `E2` 返回。

### 闭包表达式

zinc 的闭包语法与 rust 不同。zinc 在设计闭包语法的时候主要有以下几点考虑：
1. 闭包语法需要适合 “尾随调用” 语法糖。尾随调用语法在很多场景下可以设计出很美观漂亮的 DSL。比如 lock / spawn / lazy 等函数，都很适合用尾随闭包语法。
2. 闭包既要有完整写法，又要有简略写法
3. 完整写法的闭包语法，功能要完善，要支持显式捕获列表、泛型声明、完整参数列表、显式返回类型
4. 简略写法足够简略，允许省略掉一切不必要的语法元素，但也要和完整写法有相似度

完整写法的闭包语法，示例如下：
```
.{
    async [move x, weak y, ref z]<T>(arg: T) -> ReturnTy where T: Constrait
    =>
    statements(x, arg);
    return y;
}
```

完整的闭包语法以 `.{` 开头，`}` 结尾，方便与 “尾随调用” 语法配合。内部包含的内容有：
1. qualifier 修饰符列表，包括 `async` `const` 等
2. 中括号包含的显式捕获列表，捕获模式支持 `move` `ref` `ref mut` `weak`
3. 尖括号包含的泛型参数列表
4. 小括号包含的函数参数列表
5. `->` 后面跟随的显式返回类型
6. 可选的 where 条件
7. `=>` 后面跟随的闭包函数体

最简略的写法，示例如下：
```
(x) => x + x
```
小括号里面是参数列表，参数允许省略掉类型声明。`=>` 后面是闭包函数体，在没有大括号的情况下，这个函数体只能是一个表达式，不可以包含语句。

### 循环语句

#### `while`

1. while 后面的条件必须是 Bool 类型表达式
2. while 的大括号后面不需要写分号

#### `do-while`

1. while 后面的条件必须是 Bool 类型表达式
2. do-while 在语句结束最后必须写分号

#### `for`

`for  <pattern> in <expr>  { <statements> }`

1. for 支持模式匹配
2. expr 必须是满足 `Iterable` 或者 `IterableMut` trait 的类型，或者是指向这种类型的指针。

`for-in` 语句的解糖方式有三种，取决于 `<pattern>` 的写法：

1. pattern 是 identifier: `for i in v { <body> }`，此时 `i` 的类型为 `v` 的 `Iterable::Item` 类型。解糖为：

    ```
    {
        let mut iter = v.iter();
        while (iter.next() is Some(p)) { // p 是指向 Item 的只读借用
            let i = *p;                // i 是从只读借用拷贝出来的新的 Item
            <body>
        }
    }
    ```

2. pattern 是 ref identifier: `for ref i in v { <body> }`，此时 `i` 的类型为 `v` 的 `&Iterable::Item` 类型。解糖为：

    ```
    {
        let mut iter = v.iter();
        while (iter.next() is Some(i)) { // i 是指向 Item 的只读借用
            <body>
        }
    }
    ```

3. pattern 是 ref mut identifier: `for ref mut i in v { <body> }`，此时 `i` 的类型为 `v` 的 `&mut Iterable::Item` 类型。解糖为：

    ```
    {
        let mut iter = v.iter_mut();
        while (iter.next() is Some(i)) { // i 是指向 Item 的可读写借用
            <body>
        }
    }
    ```

### 跳转语句

#### `return`

1. return 后面可以接表达式也可以没有。
2. return 后面的表达式的类型必须与函数返回类型兼容。

#### `break`

1. break 只能用在循环块中。包括 `while` `do-while` `for`。

#### `continue`

1. continue 只能用在循环块中。包括 `while` `do-while` `for`。

#### `panic`

panic 关键字可以类比为 C++/Java 等语言中的 throw 关键字。但 Zinc 里面没有 try-catch 语法，也不提供 `catch_unwind` 函数。

只有发生无法恢复的错误的时候，才应该使用 panic。panic 关键字后面可以跟随一个字符串类型的表达式。示例如下：

```rust
fn unwrap<T>(o: Option<T>) -> T {
    if o is Some(v) {
        return v;
    } else {
        panic "unwrap Option failed";
    }
}
```

#### `goto`

`goto` 为预留关键字，暂时未实现。为好几个目的而准备。

1. 通过与 label 标签语句配合，实现跳转功能。替换 rust 的 break label 语句。主要是 break label 的使用场景受限，只能在循环块中使用。但 goto label 在 C 语言中还有一个更常用的场景：就是把错误处理统一写到函数末尾，在函数其它地方碰到错误都 goto 到这里统一处理。这么写极其方便易读。这个场景使用 goto 是非常合理的。当然，为了避免程序员滥用，我们应该对 goto 语句做一些限制：
    1. goto 是语句，不能用在表达式里面。
    2. 不能跨函数、lambda 跳转。
    3. 只能跳出 block，不能跳入 block。循环体、match的不同分支也是不同的 block。
    4. 只能往后面跳转，不允许往前面跳转。
    5. 必须确保在 goto 路径上，所有的变量都满足先初始化再使用。

    总之，我希望提供安全可靠的 goto 语句。既能实现 C 语言常用的，函数尾部统一错误处理的编程模式，又不带来其它的风险。

2. 为 “确定性尾递归” 特性准备。取代 rust 的 `become` 关键字。
    1. 允许用  `goto call_fn();` 实现确定性尾递归。


## 函数

函数定义以 `fn` 关键字开始，后跟着函数名和参数列表，参数列表用圆括号包围，接着是可选的返回类型，最后是大括号包围的函数体。

```rust
// 函数定义
fn function_name(arg1: Int, arg2: Char) -> Bool {
    println("function body");
    return true;
}

fn main() {
    function_name(0, 'X'); // 函数调用
}
```

省略返回类型，代表返回 `()` 类型。

参数支持命名参数，命名参数用小数点开头。调用的时候如果使用命名参数，也是使用小数点开头。用小数点语法是为了和结构体初始化表达式语法一致。
命名参数必须在非命名参数的后面。

```
fn run(.from: &Str, .to: &Str) {
    println("run from {} to {}", from, to);
}

fn main() {
    run("home", "bar");  // 可以按参数顺序调用
    run(.to = "bar", .from = "home"); // 也可以按名字调用，此时顺序不重要。
}
```

由于函数支持了命名参数，那么再支持参数的模式匹配就有点复杂了。况且在函数参数位置，大部分模式都没什么用，因此函数的参数不支持模式匹配。
在 Rust 中，参数列表支持的最有用的一个模式就是 `mut` 模式，允许参数本身被修改。在 zinc 中，建议大家用这种方式规避：
```
fn f(v: Vec<Int>) {
    let mut v = move v; // 参数中的 v 是没有 mut 修饰的，可以在函数内部再定义一个同名的 mut 变量，将参数 move 过来即可。
    // ...
    v.push(2); // 需要获取 v 的 &mut 型借用，这里要求变量 v 是 mut 修饰的
    // ...
}
```

参数支持默认值，默认值必须是常量表达式。带默认值的参数，必须在没有默认值的参数后面。

```
fn increase(value: Int = 1) {}

fn main() {
    increase();  // 实参的值为 1
    increase(2); // 实参的值为 2
}
```

支持尾随闭包。尾随闭包调用语法的含义是：如果函数定义的时候，最后一个参数的类型是fn/Fn/FnMut类型、或者是指向它们的指针类型，那么调用的时候可以把 lambda 写到参数列表的外面。
如果除了这个函数类型参数之外没有其它参数了，调用方可以省略参数列表需要的小括号。
示例如下：

```
// 函数 lock 的最后一个参数是函数类型
fn lock(f: &Fn()) {
    println("lock");
    f();
    println("unlock");
}

fn main() {
    lock( ()=>println("smth") ); // OK, 简单语法的 lambda 作为参数
    lock( .{ () => println("smth"); } ); // OK, 完整语法的 lambda 作为参数

    // 尾随闭包调用语法，把闭包写到参数列表的外面
    lock().{
        () => println("smth");
    };
    // 尾随闭包调用语法，没有其它参数的时候，省略参数列表的小括号
    lock.{
        () => println("smth");
    };
    // 后续还可以更进一步简化 lambda 的语法，允许省略 => 符号
    lock.{
        println("smth");
    };
}
```

支持函数重载。但要求参数个数不同。

```
fn f1(arg1: Int, arg2: Int = 1) {} // 允许接受 1 和参数或者 2 个参数。
fn f1(arg: String) {} // 错误，不能和上面的 f1 形成重载。这个版本允许接受 1 个参数，上面的版本也允许。发生冲突。
```

todo: 暂时不支持变长参数，待后续改进。建议一般情况使用函数重载代替，参数数量太多的场景用数组和切片来代替。

支持通过 `impl` 块给类型增加成员函数。
第一个参数名字是 `self` 关键字的时候，允许通过小数点形式调用函数。

```rust
impl User {
    fn send_email(&self) {}
}
fn main() {
    let u: User = { ... };
    u.send_email();
}
```

`self` 参数是特殊的，它有几个简化写法：
* `self` 代表 `self: Self`
* `&self` 代表 `self: &Self`
* `&mut self` 代表 `self: &mut Self`
* `*self` 代表 `self: *Self`
* `*weak self` 代表 `self: *weak Self`

函数可以当一等公民使用。支持函数指针类型。
