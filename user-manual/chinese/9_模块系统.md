# 模块系统

## 组件 (component)

zinc 的编译单元是组件。对应 rust 的 crate。

> In C and C++ programming language terminology, a translation unit (or more casually a compilation unit) is the ultimate input to a C or C++ compiler from which an object file is generated.

编译单元，指的是执行一次编译器进程，需要的源码文件。这些源码文件，是编译器执行一次编译的最小输入单元，无法继续拆分。继续拆分之后就不能执行一次编译了。

对 C/C++ 编译器来说，编译单元就是一个 .c 或者 .cpp 源文件，以及它直接和间接 `#include` 进来的所有文件。

对 Rust 编译器来说，编译单元就是一个 crate。用户不可能把一个 crate 内部的多个 mod 分别编译。

对 Zinc 编译器来说，编译单元是一个组件(component)。编译器每次执行的输入是一个完整的组件的源代码。用户不能把一个组件的多个源文件分别编译，再组装成一个组件，编译器没有这个能力。一个组件必须做为一个整体编译。

组件与组件之间不可循环依赖。

组件内部有模块(mod)，组件内部的模块之间可以循环依赖。因为同一个组件内的所有模块，是在一个编译器进程中一起编译的。

组件在编译之后，会生成包含机器码的 `.o` 文件，以及该组件的对外公开接口 `.zno` 文件。 zno 取名来源于 “氧化锌” 物质。

`.zno` 文件可以理解为 C 语言中的 “头文件”，只是头文件是人工编写的，而 `.zno` 文件是编译器自动生成的。

`.zno` 文件内容，包含所有的公开的函数签名、类型定义、全局变量声明、impl声明等。还包含所有可以跨组件内联的函数的函数体。

## `export`

如果一个组件是库，那么需要用户使用 `export component_name;` 来声明这个组件的名字。
如果一个组件是可执行程序，那么需要用户在 root mod 里面定义一个 `fn main()` 函数作为程序入口。
如果一个组件中，这两个都没有，编译器会报错。

在 Rust 中 crate 的名字是由编译选项 `--crate-name NAME` 指定的，我认为这个不合理，组件的名字应该由它的源码指定。
毕竟组件的名字影响了二进制中的符号的 mangle name，组件名字由编译选项控制，难以保证不同编译环境下编译结果的一致性。

## `import`

当我们要描述一个组件 a，依赖另外一个组件 b 的时候，需要在 a 的源码中写 `import b;`。它基本等同于 Rust 的 `extern crate b;` 的意思。

如果用 C/C++ 语言做类比，可以简单理解为 `#include "b.h"` 的意思。

## mod 介绍

模块（mod）是 Zinc 中组织代码的基本单元。模块可以包含函数、类型、常量、以及其他模块。

### 模块定义

使用 `mod` 关键字定义模块：

```rust
// 在文件中定义模块
mod my_module {
    fn helper() -> Int {
        return 42;
    }
    
    pub fn public_function() {
        println(f"helper returned $(helper())");
    }
}
```

### 文件系统模块

模块也可以通过文件系统组织。如果一个模块没有内容，编译器会查找同名的文件或目录：

```rust
// 在 main.zn 中
mod network;

// 编译器会查找：
// 1. network.zn 文件
// 2. network/mod.zn 文件
```

### 可见性

模块中的项默认是私有的，只能在定义它的模块内部访问。使用 `pub` 关键字可以使项对外可见：

```rust
mod my_module {
    pub fn public_function() {
        // 可以从外部访问
    }
    
    fn private_function() {
        // 只能在 my_module 内部访问
    }
    
    pub struct PublicStruct {
        pub field: Int,      // 公开的成员
        private_field: Int,  // 私有的成员
    }
}
```

### 嵌套模块

模块可以嵌套定义，形成树形结构：

```rust
mod outer {
    pub fn outer_function() {}
    
    mod inner {
        pub fn inner_function() {}
        
        mod deeply_nested {
            pub fn deep_function() {}
        }
    }
}
```

### 模块路径

使用 `::` 运算符访问模块中的项：

```rust
fn main() {
    outer::outer_function();
    outer::inner::inner_function();
    outer::inner::deeply_nested::deep_function();
}
```

### 可见性修饰符

Zinc 支持以下可见性修饰符：

1. **默认（私有）**：只能在定义它的模块内部访问
2. **`pub`**：对所有模块可见
3. **`pub(in path)`**：只在指定路径的模块内可见（> **计划中的功能**：未来支持）

```rust
mod my_module {
    pub fn public_api() {}
    
    fn internal_helper() {}
    
    // 未来支持：只在父模块可见
    // pub(super) fn parent_visible() {}
}
```

### 重新导出

使用 `pub use` 可以重新导出其他模块的项：

```rust
mod inner {
    pub fn helper() {}
}

mod outer {
    // 重新导出 inner::helper
    pub use inner::helper;
}

fn main() {
    // 可以通过 outer::helper 访问
    outer::helper();
}
```

### 模块与组件的关系

> **计划中的功能**：考虑支持 export path 和 import path 功能。即不仅允许 `export ident;` `import ident;`这种写法，还应该允许 `export ident1::ident2::ident3;` 和 `import ident1::ident2::ident3;` 这种写法。

主要是考虑到，如果组件与组件之间只有并列关系，没有包含关系，不够灵活。
一个组件内部的逻辑结构是树形结构，如果组件和组件没有包含关系，只有并列关系，那么当一个组件规模过大编译时间过长，需要重构的时候，重构本身就必然改变组件的逻辑结构。这是不合适的。

可以考虑允许组件内部的某个子树也可以是一个组件，而不止是模块，有助于把大型组件分割成不同的编译单元，而不影响组件内部的逻辑结构。

我们需要保持两个原则不变：
1. 一个组件的逻辑结构是树，而不是森林
2. 组件与组件之间不可循环依赖

## use 语句

`use` 语句用于将其他模块中的项引入当前作用域，避免每次都写完整的路径。

### 基本用法

```rust
use std::collections::HashMap;

fn main() {
    let map = HashMap::new();
    // 可以直接使用 HashMap，不需要写完整路径
}
```

### 路径关键字

- `self`：可访问当前 mod
- `super`：可访问当前 mod 的上一级 mod
- `::ident`：可访问全局范围内的名字，即 component 名字。合法的名字包含 export 中定义的自己的名字、import 进来的依赖项的名字、以及 std 标准库。
- `::self`：可访问当前 component 的顶层 mod。等价于通过 `::ident` 开头访问本组件的顶层名字。注：跟 Rust 有区别。在 Rust 中，是通过 `crate::` 关键字访问顶层 mod 的。

### 示例

```rust
mod outer {
    pub fn outer_fn() {}
    
    mod inner {
        pub fn inner_fn() {}
        
        fn example() {
            // 使用 self 访问当前模块
            self::inner_fn();
            
            // 使用 super 访问父模块
            super::outer_fn();
        }
    }
}

// 使用 use 导入
use outer::inner::inner_fn;

fn main() {
    inner_fn();
}
```

### 重命名导入

使用 `as` 关键字可以重命名导入的项：

```rust
use std::collections::HashMap as Map;

fn main() {
    let map = Map::new();
}
```

### 导入多个项

```rust
use std::collections::{HashMap, HashSet};

fn main() {
    let map = HashMap::new();
    let set = HashSet::new();
}
```
